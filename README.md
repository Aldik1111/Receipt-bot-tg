# Бюджетный бот с распознаванием чеков (Telegram)

Распознавание чека — через **Google Gemini** (бесплатный лимит, мультимодальная
модель понимает фото целиком, поэтому устойчива к плохому качеству и кривой
съёмке). База — **SQLite** (файл, не нужен отдельный сервер БД).

## Что умеет

- 📸 Присылаешь фото чека → Gemini распознаёт магазин, дату, время, товары и
  цены, бот раскладывает товары по категориям по локальному словарю и
  сохраняет.
- ⚡️ **Быстрый ввод без единого клика** - просто напиши сообщением сумму и
  описание: `500 такси` или `+50000 зарплата` (знак `+` = доход). Категория
  подбирается автоматически, поправить её можно одной кнопкой под сообщением.
- 📎 Чек можно прислать и как **файл** (не как фото) - Telegram тогда не
  сжимает изображение, распознавание работает точнее.
- ➕ Пошаговое добавление расхода/дохода через `/add` (для случаев, когда
  нужен полный контроль над категорией и способом оплаты).
- 📊 `/stats` — статистика за день/неделю/месяц/3 месяца/год: сумма расходов
  и доходов + круговая диаграмма по категориям.
- 🏷 Свои категории (`/categories`, `/addcategory`).
- 💳 Несколько способов оплаты — нал, разные карты/банки (`/payments`, `/addpayment`).

## Как это устроено (архитектура)

```
receipt_bot/
├── bot.py              # точка входа: команды, кнопки, сценарии диалога (aiogram)
├── config.py           # токен, ключ Gemini, категории и способы оплаты по умолчанию
├── db.py                # вся работа с SQLite (создание таблиц, CRUD)
├── receipt_pipeline.py   # вызывает gemini_engine и раскладывает товары по категориям
├── gemini_engine.py       # запрос к Google Gemini API, разбор JSON-ответа
├── categorizer.py           # определяет категорию товара по ключевым словам
├── charts.py                 # рисует графики статистики (matplotlib)
├── requirements.txt
└── .env.example
```

### Путь одного чека от фото до записи в базу

1. **Пользователь шлёт фото** → `bot.py` скачивает файл во временную папку.
2. **`gemini_engine.py`** отправляет фото в Google Gemini с промптом вернуть
   строгий JSON: магазин, дата, время, список товаров с ценами, итог.
3. **`receipt_pipeline.py`** получает результат и, если товары нашлись,
   передаёт каждый товар в **`categorizer.py`**, который сравнивает название
   со словарём ключевых слов (молоко/хлеб/такси/аптека и т.д.) и проставляет
   категорию — это отдельный бесплатный локальный шаг, не требует ещё одного
   запроса к Gemini.
4. Бот показывает **предпросмотр** результата с кнопками "✅ Сохранить" /
   "❌ Отмена" - Gemini обычно точнее классического OCR, но не идеален,
   поэтому финальное решение всегда за пользователем.
5. При подтверждении **`db.py`** создаёт запись в таблице `receipts` (шапка
   чека) и по одной транзакции в таблице `transactions` на каждый товар — так
   статистика по категориям считается позиционно, а не только по чеку целиком.

### Стоимость эксплуатации

Google Gemini API, бесплатный тариф (модель `gemini-flash-latest`):
- **~1500 запросов в день**, ~15 запросов в минуту - лимиты обнуляются каждые
  сутки, действуют на один API-ключ
- Карта не нужна, ключ бесплатный: https://aistudio.google.com/apikey

Один чек = один запрос. Для личного использования (даже 20-30 чеков в день)
упереться в этот лимит практически нереально - хватит с огромным запасом.
Google периодически меняет эти лимиты (в 2026 уже несколько раз урезала), так
что не воспринимай цифру как вечную гарантию, но на сегодняшний день бот
может работать полностью бесплатно.

## Установка

### 1. Python-зависимости

```bash
python3 -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Токен бота

1. В Telegram напиши **@BotFather** → `/newbot` → следуй инструкциям →
   получишь токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxx`.
2. Скопируй `.env.example` в `.env` и вставь свой токен:

```bash
cp .env.example .env
# отредактируй .env, впиши BOT_TOKEN
```

### 3. Ключ Google Gemini (обязательно)

Без него бот не сможет распознавать чеки:

1. Открой https://aistudio.google.com/apikey
2. Войди через Google-аккаунт, нажми "Create API key"
3. Скопируй ключ и вставь в `.env`:

```
GEMINI_API_KEY=твой_ключ_сюда
```

Ключ может выглядеть как `AIzaSy...` (старый формат) или `AQ.Ab...` (новый
формат, с середины 2026 Google выдаёт именно такие) - оба работают, код уже
умеет с ними работать.

### 4. Запуск

```bash
python3 bot.py
```

Бот работает в режиме polling (сам стучится в Telegram за обновлениями) -
не нужен ни домен, ни HTTPS, ни открытые порты. Это, кстати, сильно упрощает
хостинг - см. раздел ниже.

## Как перевести бота на постоянную работу (не с домашнего ПК)

Поскольку бот работает через polling, ему нужен только сервер с постоянным
доступом в интернет и Python - никакой публичный адрес не требуется.

### Вариант 1 - Oracle Cloud Free Tier (бесплатно навсегда)

Самый выгодный вариант: Oracle даёт **вечно бесплатную** виртуальную машину
(до 4 ARM-ядер, 24 ГБ RAM - для одного бота это огромный запас с нуля).

1. Зарегистрируйся на https://www.oracle.com/cloud/free/ (нужна карта для
   верификации личности, но с неё ничего не спишется на бесплатном тарифе)
2. Создай Compute Instance - выбери **Ampere A1 (ARM), Always Free**,
   образ Ubuntu
3. Подключись по SSH, дальше - как на обычном Linux-сервере:

```bash
sudo apt update && sudo apt install -y python3-pip python3-venv git
git clone <твой репозиторий>   # или просто scp файлы на сервер
cd receipt_bot
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впиши BOT_TOKEN и GEMINI_API_KEY
```

4. Чтобы бот работал постоянно и сам перезапускался при сбое/перезагрузке
   сервера - заведи systemd-сервис:

```bash
sudo nano /etc/systemd/system/receipt-bot.service
```

```ini
[Unit]
Description=Receipt Telegram Bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/receipt_bot
ExecStart=/home/ubuntu/receipt_bot/venv/bin/python3 bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable receipt-bot
sudo systemctl start receipt-bot
sudo systemctl status receipt-bot   # проверить, что запустился
journalctl -u receipt-bot -f        # смотреть логи в реальном времени
```

Теперь бот работает 24/7, переживает перезагрузки сервера и сам
перезапускается при падении.

### Вариант 2 - дешёвый VPS (если Oracle недоступен/неудобен)

Hetzner Cloud (~€4/мес), Timeweb Cloud или любой другой VPS - та же схема
установки и тот же systemd-сервис, что и в варианте 1. Отличие только в
том, что это платно (но недорого), зато без формальностей верификации,
которые иногда бывают у Oracle.

### Вариант 3 - PaaS попроще (Railway / Render)

Если не хочется возиться с SSH и systemd - можно задеплоить как обычное
Python-приложение на Railway.app или Render.com. Плюс - проще в настройке
(просто подключаешь GitHub-репозиторий). Минус - бесплatные тарифы там
ограничены по часам работы в месяц или "засыпают" при простое, для бота,
который должен быть онлайн круглосуточно, это менее надёжно, чем свой VPS.

**Рекомендация:** для личного проекта Oracle Cloud Free Tier - лучший выбор
(бесплатно навсегда, ресурсов с запасом, полный контроль). Если регистрация
там покажется муторной - любой VPS за пару долларов в месяц с тем же
systemd-сервисом решит задачу так же надёжно.

## Частые ошибки при запуске (troubleshooting)

**`404 Client Error: Not Found` от Gemini API**
Проверь, что `GEMINI_API_KEY` вообще указан в `.env` и не содержит лишних
пробелов/переносов строк при копировании. Если ошибка повторяется - в логах
теперь печатается полный текст ответа API (не только код), пришли его сюда.

**Бот не отвечает вообще**
Проверь `BOT_TOKEN` и что сам процесс `python3 bot.py` запущен и не упал -
смотри логи в терминале (или `journalctl -u receipt-bot -f`, если бот на
сервере через systemd).

## Известные ограничения и как их обходить

- **Gemini не настроен / ключ неверный** - шаг распознавания просто ничего
  не находит, бот попросит добавить трату вручную (`/add` или быстрый
  текстовый ввод).
- **На фото нет чека вообще** - это нормально, Gemini в этом случае вернёт
  пустой список товаров, бот сообщит об этом.
- **Предпросмотр перед сохранением остаётся всегда** - Gemini не даёт
  формальной 100%-й гарантии точности, поэтому финальное решение
  ("✅ Сохранить" / "❌ Отмена") всегда за пользователем.

## Возможные следующие шаги (когда захочешь развивать проект)

- Редактирование отдельных позиций чека перед сохранением (сейчас — только
  "сохранить всё" или "отменить всё").
- Telegram Mini App для более наглядной статистики (графики, фильтры) —
  само API уже даёт все нужные данные через `db.get_transactions()`.
- Лимиты по категориям с уведомлениями о приближении к бюджету.
- Экспорт в CSV/Excel.

## Mini App (веб-дашборд внутри Telegram)

Новые файлы: `webapp_auth.py` (проверка подписи initData), `webapp_api.py`
(HTTP API на aiohttp, порт 8000, только 127.0.0.1), `webapp/index.html`
(сам дашборд: обзор/операции/бюджеты/цели).

### Деплой на сервере (после того как Caddy+HTTPS уже настроены)

1. `pip install -r requirements.txt` (добавился aiohttp)
2. Второй systemd-сервис для API, аналогично боту:

```ini
# /etc/systemd/system/receipt-webapp.service
[Unit]
Description=Receipt Bot Mini App API
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/receipt_bot
EnvironmentFile=/home/ubuntu/receipt_bot/.env
ExecStart=/home/ubuntu/receipt_bot/venv/bin/python3 webapp_api.py
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now receipt-webapp
```

3. Caddyfile (см. пример выше в разделе про хостинг) проксирует `/api/*` на
   этот сервис и отдаёт `webapp/index.html` как статику.
4. Регистрация в @BotFather: `/mybots` → выбери бота → Bot Settings →
   Menu Button → впиши `https://твой-домен.sslip.io/` - в чате с ботом
   появится кнопка, открывающая дашборд.

Бэкенд и фронтенд не завязаны на конкретный дизайн - можно менять
`webapp/index.html` свободно, API отдаёт чистый JSON.
