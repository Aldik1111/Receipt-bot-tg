# Бюджетный бот с распознаванием чеков (Telegram)

Распознавание чека — через **Google Gemini** (бесплатный лимит, мультимодальная
модель понимает фото целиком, поэтому устойчива к плохому качеству и кривой
съёмке). База — **SQLite** (файл, не нужен отдельный сервер БД).

Прод: Docker Compose, Caddy, бэкапы и типичные сбои — в [OPS.md](OPS.md).

## Что умеет

- 📸 Присылаешь фото чека → Gemini распознаёт магазин, дату, время, товары и
  цены, бот раскладывает товары по категориям по локальному словарю и
  сохраняет.
- 👨‍👩‍👧 `/family` — общая книга на несколько Telegram (приглашение кодом, роли
  владелец / запись / чтение). Лимит Gemini остаётся личным.
- ⭐ `/pro` — Free/Pro и оплата лимита чеков через Telegram Stars. Оферта
  и казахстанская юрисдикция — не в этом репозитории.
- ⚡️ **Быстрый ввод без единого клика** - просто напиши сообщением сумму и
  описание: `500 такси` или `+50000 зарплата` (знак `+` = доход). Категория
  подбирается автоматически, поправить её можно одной кнопкой под сообщением.
- 📎 Чек можно прислать и как **файл** (не как фото) - Telegram тогда не
  сжимает изображение, распознавание работает точнее.
- ➕ Пошаговое добавление расхода/дохода через `/add` (для случаев, когда
  нужен полный контроль над категорией и способом оплаты).
- 📊 `/stats` — статистика за день/неделю/месяц/3 месяца/год: сумма расходов
  и доходов + круговая диаграмма по категориям.
- 🏷 Свои категории (`/categories`, `/addcategory`).
- 💳 Несколько способов оплаты — нал, разные карты/банки (`/payments`, `/addpayment`).

## Как это устроено (архитектура)

```
receipt_tg_bot/
├── bot.py / webapp_api.py   # Telegram-бот и Mini App API
├── handlers/ keyboards/     # команды и кнопки
├── db.py                    # SQLite, семейные книги, тарифы
├── locales/                 # ru / kk / en
├── docker-compose.yml       # bot + webapp + Caddy
├── OPS.md                   # деплой, health, backup, rollback
└── .env.example
```

Поднять стек: `docker compose up -d --build`. Без Docker по-прежнему
`python bot.py` и отдельно `python webapp_api.py`.

### Путь одного чека от фото до записи в базу

1. **Пользователь шлёт фото** → `bot.py` скачивает файл во временную папку.
2. **`gemini_engine.py`** отправляет фото в Google Gemini с промптом вернуть
   строгий JSON: магазин, дата, время, список товаров с ценами, итог.
3. **`receipt_pipeline.py`** получает результат и, если товары нашлись,
   передаёт каждый товар в **`categorizer.py`**, который сравнивает название
   со словарём ключевых слов (молоко/хлеб/такси/аптека и т.д.) и проставляет
   категорию — это отдельный бесплатный локальный шаг, не требует ещё одного
   запроса к Gemini.
4. Бот показывает **предпросмотр** результата с кнопками "✅ Сохранить" /
   "❌ Отмена" - Gemini обычно точнее классического OCR, но не идеален,
   поэтому финальное решение всегда за пользователем.
5. При подтверждении **`db.py`** создаёт запись в таблице `receipts` (шапка
   чека) и по одной транзакции в таблице `transactions` на каждый товар — так
   статистика по категориям считается позиционно, а не только по чеку целиком.

### Стоимость эксплуатации

Google Gemini API, бесплатный тариф (модель `gemini-flash-latest`):
- **~1500 запросов в день**, ~15 запросов в минуту - лимиты обнуляются каждые
  сутки, действуют на один API-ключ
- Карта не нужна, ключ бесплатный: https://aistudio.google.com/apikey

Один чек = один запрос. Для личного использования (даже 20-30 чеков в день)
упереться в этот лимит практически нереально - хватит с огромным запасом.
Google периодически меняет эти лимиты (в 2026 уже несколько раз урезала), так
что не воспринимай цифру как вечную гарантию, но на сегодняшний день бот
может работать полностью бесплатно.

## Установка

### 1. Python-зависимости

Нужен **Python 3.12**. Версия зафиксирована в `.python-version`, пакеты —
точными пинами в `requirements.txt`.

```bash
python3 -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

После клонирования тесты запускаются без `.env` и без живой базы:

```bash
python -m unittest discover -s tests -v
```

## Резервная копия живой базы

Файл `budget.db` gitignored. Чтобы снять копию и проверить, что она
открывается как отдельная база с теми же счётчиками:

```bash
python scripts/backup_sqlite.py
python scripts/backup_sqlite.py --restore-check backups/budget-YYYYMMDD-HHMMSS.db
```

Каталог `backups/` тоже в `.gitignore` — туда попадают настоящие данные.

### 2. Токен бота

1. В Telegram напиши **@BotFather** → `/newbot` → следуй инструкциям →
   получишь токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxx`.
2. Скопируй `.env.example` в `.env` и вставь свой токен:

```bash
cp .env.example .env
# отредактируй .env, впиши BOT_TOKEN
```

### 3. Ключ Google Gemini (обязательно)

Без него бот не сможет распознавать чеки:

1. Открой https://aistudio.google.com/apikey
2. Войди через Google-аккаунт, нажми "Create API key"
3. Скопируй ключ и вставь в `.env`:

```
GEMINI_API_KEY=твой_ключ_сюда
```

Ключ может выглядеть как `AIzaSy...` (старый формат) или `AQ.Ab...` (новый
формат, с середины 2026 Google выдаёт именно такие) - оба работают, код уже
умеет с ними работать.

### 4. Запуск локально

```bash
python3 bot.py
```

Бот работает в режиме polling. Mini App отдельно: `python3 webapp_api.py`
(порт 8000). Для HTTPS-кнопки в Telegram нужен публичный URL — это уже прод.

## Прод-деплой

Основной путь — **Docker Compose** (бот + Mini App + Caddy). Подробности,
health, бэкап и откат — в [OPS.md](OPS.md).

```bash
cp .env.example .env
# BOT_TOKEN, GEMINI_API_KEY; для Mini App ещё WEBAPP_URL и DOMAIN
docker compose up -d --build
```

Без Docker: unit-файлы в `deploy/`, systemd-схема тоже в OPS.md.

После подъёма Mini App: @BotFather → Bot Settings → Menu Button →
`https://твой-домен/`.

## Частые ошибки при запуске (troubleshooting)

**`404 Client Error: Not Found` от Gemini API**
Проверь, что `GEMINI_API_KEY` вообще указан в `.env` и не содержит лишних
пробелов/переносов строк при копировании. Если ошибка повторяется - в логах
теперь печатается полный текст ответа API (не только код), пришли его сюда.

**Бот не отвечает вообще**
Проверь `BOT_TOKEN` и что процесс запущен: `docker compose logs bot`
(или `python3 bot.py` локально).

## Известные ограничения и как их обходить

- **Gemini не настроен / ключ неверный** - шаг распознавания просто ничего
  не находит, бот попросит добавить трату вручную (`/add` или быстрый
  текстовый ввод).
- **Суточная квота Gemini** - Free/Pro лимит на аккаунт; ручной ввод и банк
  его не тратят. Статус — `/pro`.
- **На фото нет чека вообще** - это нормально, Gemini в этом случае вернёт
  пустой список товаров, бот сообщит об этом.
- **Предпросмотр перед сохранением остаётся всегда** - Gemini не даёт
  формальной 100%-й гарантии точности, поэтому финальное решение
  ("✅ Сохранить" / "❌ Отмена") всегда за пользователем.

## Mini App

Дашборд внутри Telegram: `webapp/index.html` + `webapp_api.py`. Auth только
по подписи `initData`. API отдаёт JSON; вёрстку можно менять отдельно.
Деплой — Compose в OPS.md, не отдельный systemd-сервис «поверх» бота.
