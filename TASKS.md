## Пачка 3 — Бэкап v3 и restore из чата ✅ СДЕЛАНО (5 сен 2026)

Приоритет: P0. Файлы: `db.py`, `bot.py`, `tests/test_core.py`.

Сделано: `get_all_user_rows` теперь кладёт `backup_id` и `runs` (список periods
`YYYY-MM`) в каждый повтор; `restore_user_backup` переносит эти periods в
`recurring_runs` под новым id, так что после восстановления `apply_due_recurring`
не списывает уже сработавший в этом месяце платёж повторно. Версия бэкапа → 3.

В `/settings` появилась кнопка «📥 Восстановить из файла»: пользователь
присылает JSON, бот проверяет, что это валидный dict (иначе — отказ без wipe),
показывает превью счётчиков (операции/чеки/повторы/цели/категории) и просит
подтверждение кнопками «Заменить данные» / «Отмена». Восстановление и вся
проверка «свой ли черновик» завязаны на `RESTORE_SCOPE` в `app_state`,
драфт-id содержит `user_id`. Ограничение файла — 20 МБ (лимит Telegram на
скачивание документа ботом).

`restore_backup.py` (CLI-скрипт) не пришлось менять — он просто вызывает
`db.restore_user_backup`, а тот теперь сам подхватывает `runs`, если они есть
в файле, и работает как раньше со старыми (v2) бэкапами. Теперь есть и путь
в чате для тех, у кого нет доступа к серверу/CLI. `backup.py` (сборка файла
для «Скачать бэкап сейчас») тоже не трогал — он просто сериализует
`get_all_user_rows`.

Баги / дыры (были):

- `get_all_user_rows` не выгружает `recurring_runs`. После restore планировщик
  может **повторно провести** платёж в том же месяце.
- Пользователь скачивает JSON, вернуть его может только админ через CLI.
- Нет валидации файла перед wipe: битый JSON сотрёт живые данные.

Сделать:

1. Backup version 3: добавить `recurring_runs` (или `last_run` так, чтобы
   `apply_due_recurring` не сработал повторно).
2. В боте: `/settings` → «Восстановить из файла» → пользователь шлёт JSON →
   превью счётчиков → подтверждение → `restore_user_backup`.
3. Битый/чужой файл — отказ, данные не трогать.
4. Тест: restore + `apply_due_recurring` в том же месяце = 0 новых проводок.
5. Тест: невалидный JSON не вызывает wipe.

Промпт:

```
Пачка 3 из TASKS.md: backup v3 (recurring_runs) и restore из чата через /settings.
Двойное подтверждение. Битый файл не должен стирать данные.
```
